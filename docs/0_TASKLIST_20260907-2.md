我已经按 `nova-story/main` 的实际代码链路检查了一遍。结论是：**RedCraft 赤佬 / Krea 2 其实已经接了约 60–70% 的骨架，现在缺的不是“新增一个生图 Provider”，而是把当前实验性 RedCraft workflow 做成真正可部署的 INT4 / INT8 双 Profile。**

当前仓库已经有：

* `redcraft_krea2` 模型族识别；
* `backend/static/workflows/redcraft_krea2_12gb.json`；
* `compileComfyWorkflow()` 对 RedCraft 的 workflow 路由；
* RedCraft 默认 `CFG=1 / 10 steps / Euler / Simple`；
* `LoraLoaderModelOnly` 路径；
* 独立 VAE 的 img2img；
* 项目设置页已经可以选择 `RedCraft 3.0 (Krea2 静态文生图 · 12GB 推荐)`；
* bundled workflow 在 DB 初始化时会自动 seed，无需再写一套注册机制。

真正的问题在于当前 workflow 仍写死了 `redcraft_krea2_int4.safetensors` 和 `qwen_vl.safetensors` 这类占位式文件名。 当前 Krea 2 的 ComfyUI 文件体系使用 `qwen3vl_4b_fp8_scaled.safetensors` + `qwen_image_vae.safetensors`；RedCraft 当前发布则已经有 INT8/INT4 ConvRot 版本，并标注 ComfyUI 0.27 原生支持。([Hugging Face][1])

  * 例如选择：

    ```text

    ```
  * 不允许默默换成：

    ```text

    ```
  * 这类 silent fallback 会导致“任务成功但画风完全不对”，比直接失败更难排查。

* [ ] **P0-8：增加 RTX 3060 专用 Resolution Guard**

  * 当前非 SD1.5 的统一高分辨率会到：

    ```text
    standard portrait = 768×1024
    high portrait     = 1152×1536
    ```

  * 对 RedCraft + 3060，我建议第一阶段：

    ```text
    draft    576×768
    standard 768×1024
    square   1024×1024
    ```

  * `high 1152×1536` 暂时不要作为 12GB 默认。

  * 可继续允许用户显式指定，但显示“可能触发 CPU weight swapping / OOM”。

* [ ] **P0-9：INT4 为 3060 默认 Profile**

  * 不建议 RTX 3060 把 INT8 设置为默认。
  * 官方 Krea 2 的 INT8 ConvRot 权重本身约 **13.5GB**，Qwen3VL FP8 编码器又约 **5.24GB**；显然需要模型卸载/weight swapping，不能同时常驻 12GB VRAM。([Hugging Face][6])
  * RedCraft 作者也明确说明 12GB 可以依靠 weight swapping 运行。([Civitai][7])
  * 因此：

    ```text
    RTX 3060 → INT4 默认
    INT8 → 高质量/实验 Profile
    ```

# 我建议的最终架构

不要新增：

```text
RedCraftProvider
KreaProvider
RedCraftInt4Provider
RedCraftInt8Provider
```

而是继续保持现有架构：

```text
GenerationService
        │
        ├── ImageModelFamily
        │      └── redcraft_krea2
        │
        ├── RedCraftProfileResolver
        │      ├── INT4
        │      └── INT8
        │
        ├── compileComfyWorkflow()
        │
        └── ComfyUIService
                ↓
              ComfyUI
```

**`ComfyUIService` 现在已经足够通用，不应该为了 RedCraft 再造一层 Provider。** 它已经负责 `/prompt`、WebSocket、history fallback、图片下载和 cancel。

这样是改动最小、架构也最收敛的方案。

### 验收门槛

第一阶段我会把完成定义为：

```text
RTX 3060 12GB + 32GB
        ↓
Project = RedCraft Krea2
Profile = INT4
        ↓
启动自动预检
        ↓
READY
        ↓
768×1024 / 1024×1024
8~10 Steps / CFG1 / Euler Simple
        ↓
真实 PNG 正常生成
        ↓
NovaStory 正常持久化 asset
        ↓
metadata 能追踪 model/profile/seed
        ↓
缺模型时入队前明确报错
```

**优先级最高的其实只有 4 件事：Profile Resolver → 修正模型依赖 → Preflight → 真机 Smoke Test。** 这四项完成后，RedCraft 才算从“仓库里已经写了支持代码”变成“RTX 3060 上真正可用的正式生图引擎”。
