## 2. 公共模型栈与时序/分辨率契约

### 2.1 12GB 显存优化的公共模型底座
4 套 H3 工作流共享同一套经过量化与裁剪的模型组合（定义于各 `.manifest.json` 的 `required_models`）：
1. **扩散模型（UNet）**：
   - Ref2VA / Multi-Frame / 红潮 A2A 使用：`minimax_h3_ref2va_pruned_int8_convrot.safetensors`（Pruned INT8 ConvRot 量化格式）。
   - FL2VA 使用：`minimax_h3_fl2va_pruned_int8_convrot.safetensors`（首尾帧专用权重）。
2. **多模态文本编码器（CLIP）**：
   - 统一使用 `CLIPLoader` 加载 `qwen3vl_32b_minimax_h3_nvfp4_awq.safetensors`（`type: "minimax"`, NVFP4 / AWQ INT8 量化）。
3. **视频 VAE**：
   - 统一使用 `VAELoader` 加载 `minimax_h3_video_vae_fp16.safetensors`（FP16）。
4. **音频 VAE 自动补齐机制**：
   - 在 [`video_workflow_compiler.ts`](file:///Users/lm/pyProj/nova-story/backend/src/services/video/video_workflow_compiler.ts) 编译阶段，若检测到工作流中包含官方 `MiniMaxH3ReferenceToVideo` 节点（即 `ref2va` 与 `multiframe`）且尚未连接 `audio_vae`，编译器会自动新增一个 `VAELoader` 节点加载 `minimax_h3_audio_vae_fp32.safetensors` 并挂载到 `audio_vae` 输入端（同时将其追加进 `manifest.required_models`），以满足最新 ComfyUI 官方节点的输入签名要求；但最终输出仅解码视频帧（避免在 12GB 显存上执行高开销音频解码）。

### 2.2 帧率、模型帧数（`17k+5` 网格）与交付帧数契约
- **原生帧率**：所有 H3 工作流强制固定为 **`24 fps`**（若违反则编译器直接报错阻断）。
- **模型采样帧数 vs. 交付帧数**：
  - MiniMax H3 原生视频潜空间要求帧数必须落在 **`17k + 5`** 网格上（[`alignH3FrameCount`](file:///Users/lm/pyProj/nova-story/backend/src/services/video/video_spec_compiler.ts)）。
  - 对于标准 5.0 秒（`5 × 24 = 120` 帧）视频，模型实际请求生成 **`124` 帧**（`17 × 7 + 5 = 124`），随后由 [`VideoPostprocessService.standardizeVideo()`](file:///Users/lm/pyProj/nova-story/backend/src/services/video/video_postprocess_service.ts) 使用 FFmpeg 精确裁剪并重编码为 **`120` 帧（5.0 秒，`yuv420p` H.264 MP4）** 交付。
- **分辨率预设（`VideoPreset`）**：
  - `preview_480p_5s`（模板默认值）：`864 × 480`，124 模型帧 $\rightarrow$ 120 交付帧。
  - `standard_720p_5s`（正式成片默认值）：`1280 × 720`，124 模型帧 $\rightarrow$ 120 交付帧。

## 3. 各视频工作流详细能力解析

### 3.1 `minimax_h3_ref2va_official_12gb` —— 官方 Ref2VA 主力叙事工作流（默认）
- **文件**：
  - [`minimax_h3_ref2va_official_12gb.api.json`](file:///Users/lm/pyProj/nova-story/backend/static/video-workflows/minimax_h3_ref2va_official_12gb.api.json)
  - [`minimax_h3_ref2va_official_12gb.manifest.json`](file:///Users/lm/pyProj/nova-story/backend/static/video-workflows/minimax_h3_ref2va_official_12gb.manifest.json)
- **上游参考**：`Comfy-Org/workflow_templates:templates/video_minimax_h3_r2v.json`
- **节点链路**：
  - `LoadImage` (Node 4) 加载首帧 `first_frame.png` $\rightarrow$ 接入 `MiniMaxH3ReferenceToVideo` (Node 10) 的 `ref_images.ref_image_0`。
  - `LoadImage` (Nodes 5, 6, 7) 加载最多 3 张角色身份参考图 `char_ref_1..3.png` $\rightarrow$ 接入 `ref_images.ref_image_1..3`。
  - `VHS_LoadVideo` (Node 8) 加载可选运动参考视频 `motion_track.mp4` $\rightarrow$ 接入 `ref_videos.ref_video_0`。
  - `MiniMaxH3ReferenceToVideo` (Node 10) 输出 `[0]` conditioning 至 `BasicGuider` (Node 14)，输出 `[1]` latent_image 至 `SamplerCustomAdvanced` (Node 15)。
  - 采样控制：`RandomNoise` (Node 11) + `KSamplerSelect` (`res_multistep`, Node 12) + `BasicScheduler` (`normal`, `steps: 20`, Node 13) $\rightarrow$ `SamplerCustomAdvanced` (Node 15) $\rightarrow$ `VAEDecode` (Node 16) $\rightarrow$ `VHS_VideoCombine` (Node 17)。
- **动态编译与能力边界**：
  - **跨模态标签策略（`reference_tag_policy`）**：[`VideoSpecCompiler`](file:///Users/lm/pyProj/nova-story/backend/src/services/video/video_spec_compiler.ts) 会自动在正向提示词头部生成显式图号绑定指令：
    - `<Picture 1>` 固定指代镜头首帧关键帧（保持构图、光影与起始外观）。
    - `<Picture 2>, <Picture 3>, ...` 指代同一焦点角色的身份参考图（保持五官、发型、常服材质；生产规则中脸槽传定妆照 `avatar_url`，身体槽传三视图正面单人图 `turnaround_front_url`）。
    - 若传入了 `motion_reference_asset_id`，则追加 `<Video 1>` 动作时序与姿态参考说明；**若未传运动参考视频，编译器会自动从节点图中删除 Node 8 (`VHS_LoadVideo`) 及 Node 10 上的 `ref_videos.*` 输入键**，因此普通叙事镜头无需提供运动参考视频即可直接运行。
  - **门禁限制**：不支持 `last_frame_asset_id`（硬尾帧）和 `guide_frames`（中间引导帧）；若请求携带这两个参数，预检 schema 会直接报错并提示改用 `FL2VA` 或 `Multi-Frame` 工作流。

### 3.2 `minimax_h3_multiframe_official_12gb` —— 官方多帧引导与尾帧锚定工作流
- **文件**：
  - [`minimax_h3_multiframe_official_12gb.api.json`](file:///Users/lm/pyProj/nova-story/backend/static/video-workflows/minimax_h3_multiframe_official_12gb.api.json)
  - [`minimax_h3_multiframe_official_12gb.manifest.json`](file:///Users/lm/pyProj/nova-story/backend/static/video-workflows/minimax_h3_multiframe_official_12gb.manifest.json)
- **上游参考**：`Comfy-Org/workflow_templates:templates/video_minimax_h3_multiframe_reference.json`
- **节点链路**：
  - 基础身份参考与 `ref2va` 相同：Node 4 (`first_frame.png`) + Nodes 5–7 (`char_ref_1..3.png`) 接入 Node 10 `MiniMaxH3ReferenceToVideo`。
  - **多帧时间轴引导链（`MiniMaxH3AddGuide`）**：
    - Node 20 (`LoadImage` `guide_frame.png`) $\rightarrow$ Node 21 `MiniMaxH3AddGuide`（默认锚定在中间帧 `frame_idx: 60`，即 2.50 秒处）。
    - Node 22 (`LoadImage` `last_frame.png`) $\rightarrow$ Node 23 `MiniMaxH3AddGuide`（串联在 Node 21 之后，默认锚定在交付末帧 `frame_idx: 119`，即 4.96 秒处）。
  - 视频封装：使用 ComfyUI 原生 `CreateVideo` (Node 17, `fps: 24`) + `SaveVideo` (Node 18)，无需依赖第三方 `ComfyUI-VideoHelperSuite` 即可运行（`required_custom_nodes: []`）。
- **动态编译与能力边界**：
  - **支持 1～4 个任意帧位引导帧（`guide_frames`）**：
    - 当请求传入 `guide_frames: [{ filename, frameIdx }, ...]`（最多 4 个，帧索引必须在 `1..119` 之间且互不重复）时，[`VideoWorkflowCompiler.compile()`](file:///Users/lm/pyProj/nova-story/backend/src/services/video/video_workflow_compiler.ts) 会将第 1 个引导帧填入 Node 20/21，并为后续第 2～4 个引导帧**动态创建并串联新的 `LoadImage` + `MiniMaxH3AddGuide` 节点对**。
  - **动态尾帧开关**：
    - 若请求同时提供了 `lastFrameFilename`，编译器会将 Node 23（`frame_idx: 119`）串联到最后一个引导帧节点之后，并将 `BasicGuider` (Node 14) 的 `conditioning` 指向 `['23', 0]`。
    - 若未提供独立尾帧，则 `BasicGuider` 直接连接最后一个引导帧节点 `[finalGuideNode, 0]`，不强行把首帧当作第 119 帧锁死。
  - **核心优势**：解决了「既要绑定角色定妆/全身参考图，又要控制镜头中途关键动作姿态（如复杂手势、转身、施法定格）或尾帧构图」的需求。

### 3.3 `minimax_h3_fl2va_official_12gb` —— 官方首尾帧边界锁定工作流（FL2VA）
- **文件**：
  - [`minimax_h3_fl2va_official_12gb.api.json`](file:///Users/lm/pyProj/nova-story/backend/static/video-workflows/minimax_h3_fl2va_official_12gb.api.json)
  - [`minimax_h3_fl2va_official_12gb.manifest.json`](file:///Users/lm/pyProj/nova-story/backend/static/video-workflows/minimax_h3_fl2va_official_12gb.manifest.json)
- **上游参考**：`Comfy-Org/workflow_templates:templates/video_minimax_h3_i2v.json`
- **节点链路**：
  - `UNETLoader` (Node 1) 加载首尾帧专用模型 `minimax_h3_fl2va_pruned_int8_convrot.safetensors`。
  - `LoadImage` (Node 4 `first_frame.png`) 与 `LoadImage` (Node 5 `last_frame.png`) 直接输入给 `MiniMaxH3ImageToVideo` (Node 10) 的 `first_frame` 和 `last_frame` 端口。
  - 后续经 `RandomNoise` + `KSamplerSelect(res_multistep)` + `BasicScheduler(steps: 20)` + `BasicGuider` + `SamplerCustomAdvanced` $\rightarrow$ `VAEDecode` $\rightarrow$ `VHS_VideoCombine` 输出 MP4。
- **动态编译与能力边界**：
  - **纯净首尾关键帧驱动**：不生成 `<Picture N>` 或 `<Video 1>` 序号标签；若未单独传入 `lastFrameFilename`，编译器会自动用 `firstFrameFilename` 回填 `last_frame`（适合生成首尾无缝闭合的待机循环 `character_loop`）。
  - **严格参数互斥**：在 [`schemas/video.ts`](file:///Users/lm/pyProj/nova-story/backend/src/schemas/video.ts) 中，选用 `fl2va` 时严禁传入 `character_reference_asset_ids`、`motion_reference_asset_id` 或 `guide_frame_asset_id`，确保调用者清楚该模型仅靠首尾两帧图像本身维持人物外观与构图。

### 3.4 `minimax_h3_hongchao_a2a_12gb` —— 红潮 H3 A2A 混合实验工作流
- **文件**：
  - [`minimax_h3_hongchao_a2a_12gb.api.json`](file:///Users/lm/pyProj/nova-story/backend/static/video-workflows/minimax_h3_hongchao_a2a_12gb.api.json)
  - [`minimax_h3_hongchao_a2a_12gb.manifest.json`](file:///Users/lm/pyProj/nova-story/backend/static/video-workflows/minimax_h3_hongchao_a2a_12gb.manifest.json)
- **节点链路**：
  - 使用常规 `CLIPTextEncode` (Node 6 正向 / Node 7 负向) 编码提示词。
  - 通过自定义节点包 `ComfyUI-MiniMax-H3` 的 `H3Ref2VAAdapter` (Node 25) 一次性汇总：`model`、`positive`、`negative`、`first_frame` (Node 10)、`last_frame` (Node 11)、`char_ref_1..3` (Nodes 12–14) 以及 `VHS_LoadVideo` 的 `motion_video` (Node 20)。
  - 由 `EmptyLatentVideo` (Node 30) 创建视频潜空间，交由标准 `KSampler` (Node 3, `cfg: 3.5`, `euler`, `normal`) 采样，最后经 `VAEDecode` + `VHS_VideoCombine` 输出。
- **动态编译与能力边界**：
  - **独立负向提示词槽位**：4 套工作流中唯一在 Manifest 中暴露 `negative_prompt` 槽位（Node 7）并使用 `CFG = 3.5` 标准 `KSampler` 的工作流（其余 3 套官方候选图均使用 `BasicGuider` 无负向条件、`res_multistep` 20 步采样）。
  - **自适应低步数策略**：编译器针对该工作流保留了实验调优步数——当 `preset === 'preview_480p_5s'` 时自动设 `steps = 6`，当 `preset === 'standard_720p_5s'` 时设 `steps = 10`（其余 3 套官方候选工作流默认 `steps = 20`，可通过环境变量 `NOVASTORY_H3_STEPS` 覆盖）。
  - **定位说明**：标记为 `stability: "experimental"`，依赖第三方 `ComfyUI-MiniMax-H3` 节点包；正式生产流水线优先使用上述 3 套基于 ComfyUI 官方内置节点（`MiniMaxH3ReferenceToVideo` / `MiniMaxH3ImageToVideo` / `MiniMaxH3AddGuide`）的 `candidate` 工作流。

## 5. 运行时校验与生产门禁（Preflight & Identity Validation）

在提交视频生成任务前，后端通过 [`VideoRuntimeInspector`](file:///Users/lm/pyProj/nova-story/backend/src/services/video/video_runtime_inspector.ts)、[`VideoWorkflowCompiler.validateAgainstComfyObjectInfo()`](file:///Users/lm/pyProj/nova-story/backend/src/services/video/video_workflow_compiler.ts) 与 [`VideoReferenceIdentityService`](file:///Users/lm/pyProj/nova-story/backend/src/services/video/video_reference_identity_service.ts) 执行四重校验：

1. **ComfyUI 节点与模型在线完备性校验**：
   - 实时拉取 ComfyUI `/object_info`，核对编译后工作流中的所有 `class_type` 是否均已注册（如 `MiniMaxH3ReferenceToVideo`、`MiniMaxH3AddGuide`、`MiniMaxH3ImageToVideo`、`VHS_VideoCombine` 等）。
   - 核对 `UNETLoader`、`CLIPLoader`、`VAELoader` 中引用的模型文件名（含自动挂载的 `minimax_h3_audio_vae_fp32.safetensors`）是否真实存在于 ComfyUI 的可用模型列表中，并确保 `.api.json` 与 `.manifest.json` 声明的模型列表双向严格一致。
2. **单角色身份一致性门禁**：
   - H3 视频工作流一次只支持绑定**一个焦点角色身份**（`subject_references` 最多 1 个角色，且 `character_reference_asset_ids` 不可混入两个不同 `character_id` 的图片），防止将甲角色的文本外观锁错误绑定到乙角色的参考图上。
3. **合法身份底图钉选校验（[`video_identity_plates.ts`](file:///Users/lm/pyProj/nova-story/backend/src/services/video/video_identity_plates.ts)）**：
   - 视频的角色参考槽位只接收**定妆照（`avatar_url`）**和**三视图正面单人图（`turnaround_front_url`）**两张单人底图，拒绝三视图整张拼图（`turnaround_url`）、旧版裁脸图（`face_url`）或非当前钉选角色版本的野生参考图。
4. **策略自動选型优先级（生产脚本 `chooseShotVideoStrategy`）**：
   - 显式传入的工作流覆盖 $\rightarrow$ 镜头存在 `guide_frame_reference` / `composition_reference` 时自动选用 `minimax_h3_multiframe_official_12gb` $\rightarrow$ 镜头仅存在硬尾帧 `last_frame_reference` 时选用 `minimax_h3_fl2va_official_12gb` $\rightarrow$ 项目配置的默认工作流 $\rightarrow$ 兜底选用 `minimax_h3_ref2va_official_12gb`。
