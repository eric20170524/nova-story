# NovaStory 分镜生图与生视频生产最佳实践

> 日期：2026-10-03  
> 状态：产品层规范 / 实施事实源  
> 适用范围：Director 分镜生图、视频关键帧、MiniMax H3 单镜视频、批量生产与后续章节合成  
> 关联任务：`docs/0_TASKLIST.md` Track 7

---

## 1. 结论先行

NovaStory 的媒体生产统一采用“**16:9 Shot Master → 视频**”的工作流。

### 生图

- 默认画布：**16:9**
- 从产品可选画布中移除：**3:4、4:3**
- 保留：**16:9、9:16、1:1、auto**
- `auto` / `auto_by_shot` 不得再解析成 3:4 或 4:3
- 普通叙事分镜、视频关键帧默认都落到 **16:9**
- 角色立绘若需要竖构图，只允许显式选 **9:16**；头像/网格类可以显式选 **1:1**
- 历史项目中保存的 3:4 / 4:3 只作为旧数据读取兼容，不再作为新建/编辑可选值；读取后统一迁移或归一为 16:9

### 生视频

- 默认：**16:9 / 1280×720 / 24fps**
- 可选低成本预览：**480p / 24fps**
- MiniMax H3 **必须保持原生 24fps**
- UI 不提供 30fps / 60fps 等 H3 帧率选项
- 现有 5 秒产品合同继续保留：
  - H3 模型侧：124 帧（满足 H3 `17k+5` 帧数网格）
  - 成片侧：120 帧
  - 成片时长：5.0 秒
  - 成片帧率：24fps
- 720p 与 480p 只切换空间分辨率/成本，不改变时间基和 fps

---

## 2. 为什么统一 16:9

NovaStory 的目标不是分别维护“漫画竖图”和“视频横图”两套镜头真值，而是建立一个可以贯穿：

```text
剧本
  ↓
镜头契约
  ↓
16:9 Shot Master
  ↓
H3 视频
  ↓
章节剪辑 / 字幕 / TTS / BGM
```

的统一生产链。

16:9 Shot Master 同时承担：

1. 最终构图；
2. 场景与道具位置；
3. 多角色站位和尺度关系；
4. 景别与机位；
5. 光线、色调与环境状态；
6. 视频首帧视觉真值。

因此，视频阶段不应重新把“纯场景图 + 多张人物图 + 首帧图”无差别交给模型再次组合。**场景资产和角色资产主要用于生成正确的 Shot Master；视频模型以 Shot Master 为最高优先级。**

## 3. 生图画布契约

### 3.1 新产品枚举

推荐前后端统一为：

```ts
type ImageAspectRatio =
  | '16:9'
  | '9:16'
  | '1:1'
  | 'auto';
```

不再允许新请求写入：

```text
3:4
4:3
```

### 3.2 默认值

```json
{
  "aspect_ratio": "16:9",
  "resolution": "standard",
  "orientation_policy": "fixed"
}
```

### 3.3 auto 规则

现有实现中 `auto_by_shot` 会解析成 4:3 / 3:4，这与新规范冲突，必须一起修改。

新规则：

| 类型 | auto 解析 |
|---|---|
| 普通 scene / storyboard | 16:9 |
| video_keyframe | 16:9 |
| portrait | 16:9 默认；仅用户显式选择时使用 9:16 |
| turnaround | 不再隐式使用 4:3；由专用 compositor 使用内部 panel 尺寸，最终对外资产采用受支持画布 |
| cinematic_grid / contact sheet | 1:1 |
| 明确竖版内容 | 9:16 |
| 其它 | 16:9 |

原则：**auto 是布局策略，不得成为重新引入 3:4 / 4:3 的后门。**

### 3.4 历史数据迁移

历史项目可能保存：

```json
{ "aspect_ratio": "3:4" }
```

或：

```json
{ "aspect_ratio": "4:3" }
```

迁移策略：

```text
3:4 → 16:9
4:3 → 16:9
```

要求：

- 老项目可打开；
- 不因为旧值导致 Zod/TS 崩溃；
- 保存项目时写回新值；
- 新 UI 不再显示 3:4 / 4:3；
- 不回写修改历史图片文件本身，只修改后续生成默认契约。

## 4. 生视频交付契约

### 4.1 默认生产档

```text
Preset: standard_720p_5s
Canvas: 16:9
Delivery: 1280×720
FPS: 24
Duration: 5.0s
Delivery frames: 120
```

这是 Director 新任务的默认值。

### 4.2 480p 预览档

```text
Preset: preview_480p_5s
FPS: 24
Duration: 5.0s
Delivery frames: 120
```

480p 用于：

- RTX 3060 12GB 首次 smoke test；
- 动作/提示词快速试错；
- 批量低成本预览；
- 复杂镜头在升 720p 前的可行性验证。

现有 H3 12GB 工作流可继续使用模型安全的 480p 工作尺寸；产品层仍将该档视为 16:9 预览档。若后续要求像素级严格 16:9，统一在 postprocess 层规范化，**不要为了凑尺寸改变 H3 原生 24fps 或帧数规则。**

### 4.3 24fps 是硬约束

MiniMax H3 在 NovaStory 中统一：

```text
model fps = 24
delivery fps = 24
timeline fps = 24
QA fps = 24
```

禁止：

- 默认改成 30fps；
- H3 生成后为了“更顺”做 30/60fps 插帧再作为主成片；
- 不同 Scene 混用不同 fps 后直接章节拼接；
- UI 暴露任意 fps 输入框。

如果未来其它 provider 原生不是 24fps，必须在 provider 边界显式声明自己的时基，不能反向污染 H3 合同。

### 4.4 H3 帧数

5 秒 × 24fps = 120 个交付帧。

但 H3 模型长度需满足 `17k+5`，所以：

```text
requested delivery = 120
model generation   = 124
postprocess        = 120
final duration     = 5.0s
```

这不是“多生成 4 帧给用户”，而是模型内部约束。

## 5. Shot Master：视频最高优先级参考

一个可进入视频阶段的 Shot Master 必须已经正确表达：

- 场景；
- 角色；
- 角色站位；
- 道具；
- 镜头构图；
- 景别；
- 相机角度；
- 光照和色调；
- 当前服装/角色版本；
- 当前剧情状态。

因此生产顺序必须是：

```text
Scene / Character / Location / Prop assets
        ↓
生成并验收 16:9 Shot Master
        ↓
视频 Reference Binding
        ↓
H3
```

如果 Location / Prop / Character Version 发生改变，Shot Master 必须失效并重新生成；不能继续拿旧首帧加新参考图硬做视频。

## 6. 视频参考素材优先级

推荐优先级：

```text
1. Shot Master / first frame
2. Character identity refs
3. Guide frame
4. Motion reference video
5. Last frame
```

每一种素材只承担一个职责。

### 6.1 Shot Master

职责：**画面真值**

控制：

- 构图；
- 场景；
- 角色位置；
- 光线；
- 道具；
- 起始姿态。

### 6.2 Character identity refs

职责：**身份真值**

推荐：

- 1–2 张高质量图为默认；
- 上限仍可保留 3 张；
- 正面 / 3⁄4 脸部 + 当前服装半身/全身是最有价值组合。

不要为了“参考更多”机械塞满 3 张。多图之间出现不同服装、发型、年龄、画风，会增加冲突。

### 6.3 Guide Frame

职责：**关键动作姿态 / 中间构图**

适合：

- 拔剑；
- 转身；
- 手部动作；
- 双人交互；
- 大幅肢体动作；
- 需要在某个时间点稳定空间关系的镜头。

优先使用 Official Multi-Frame 工作流。

### 6.4 Motion Reference

职责：**动作时序和身体轨迹**

只提供：

- 动作节奏；
- 姿态轨迹；
- 时间关系。

不得让 motion reference 提供人物身份。

### 6.5 Last Frame

职责：**结束边界**

适合：

- 指定最终姿态；
- 镜头接续；
- loop；
- 需要强首尾边界的 FL2VA。

---

## 7. 工作流选择

### 普通单角色叙事镜

优先：

```text
Official Ref2VA
Shot Master + 1–2 identity refs
```

### 复杂动作镜

优先：

```text
Official Multi-Frame
Shot Master + identity refs + guide frame
```

### 强首尾边界

优先：

```text
Official FL2VA
first frame + last frame
```

### 红潮 Hybrid

定位：

```text
experimental / compatibility / benchmark
```

不再建议作为产品默认工作流。它可以继续保留用于 A/B 与本机实验，但生产默认应优先官方可验证工作流。

## 8. 多角色镜头

当前 NovaStory 的 `character_reference_asset_ids` 虽然允许 1–3 张图，但语义是：

> 同一个 Character 的 1–3 张身份参考。

当前服务会阻止一次请求混入多个不同 `character_id`。

因此当前多角色镜头的正确实践是：

1. 先生成并验收包含所有角色的 16:9 Shot Master；
2. Shot Master 锁定人物站位、尺寸和构图；
3. 不把不同角色图片伪装成“同角色多参考”；
4. 视频阶段优先依赖完整首帧；
5. 身份稳定不足时，再推进真正的多 Subject Reference 契约。

未来建议的数据结构：

```ts
subject_references: [
  {
    character_id: 101,
    asset_ids: [1001, 1002]
  },
  {
    character_id: 102,
    asset_ids: [1101, 1102]
  }
]
```

在该契约实现前，不解除现有 mixed-identity fail-closed 门禁。

## 9. Multi-Frame 后续方向

当前只支持单个：

```text
guide_frame_asset_id
guide_frame_idx
```

后续建议扩展成：

```ts
guide_frames: [
  { asset_id: 201, frame_idx: 36 },
  { asset_id: 202, frame_idx: 72 },
  { asset_id: 203, frame_idx: 108 }
]
```

24fps 下：

- frame 24 ≈ 1.0s
- frame 36 ≈ 1.5s
- frame 48 ≈ 2.0s
- frame 72 ≈ 3.0s
- frame 96 ≈ 4.0s

这样可以把分镜导演意图直接映射到时间轴关键姿态。

## 12. 验收标准

### 生图

- [ ] 新项目默认 16:9。
- [ ] Project Settings 不再出现 3:4 / 4:3。
- [ ] Director 不再显示 3:4 默认值。
- [ ] API schema 不接受新写入的 3:4 / 4:3。
- [ ] 旧项目 3:4 / 4:3 能正常打开并迁移到 16:9。
- [ ] auto 不再解析成 3:4 / 4:3。
- [ ] 普通 storyboard / video keyframe 默认共享 16:9 构图合同。

### 生视频

- [ ] Director 默认 720p。
- [ ] 480p 仍可显式选择。
- [ ] 所有 H3 preset 固定 24fps。
- [ ] UI 无 30fps / 60fps H3 选项。
- [ ] 720p 成片为 1280×720 / 24fps / 120f / 5.0s。
- [ ] 480p 成片保持 24fps / 120f / 5.0s。
- [ ] H3 模型输入仍按 124 帧长度规则，交付裁为 120 帧。
- [ ] 章节合成拒绝混入非 24fps H3 成片。

### Reference

- [ ] Shot Master 是视频第一优先级视觉真值。
- [ ] 同角色身份参考默认推荐 1–2 张，上限 3 张。
- [ ] 不解除 mixed-character identity fail-closed。
- [ ] Multi-Frame guide frame 能按 24fps 时间轴解释 frame_idx。
- [ ] 场景/道具/角色版本变化后，旧 Shot Master 不能继续通过视频 preflight。

## 13. 不做事项

本轮不做：

- 把 H3 改成 30fps；
- 30→24 或 24→30 作为默认主链；
- 用光流插帧制造“高帧率 H3”；
- 把 3:4 / 4:3 继续藏在 auto 策略里；
- 一次请求强行混入不同角色 ID 的 character refs；
- 为了 720p 默认而删除 480p smoke-test 能力；
- 为了统一 16:9 覆盖或重写历史图片资产。

## 14. 最终生产链

```text
Script / Storyboard Contract
        ↓
Character / Location / Prop Binding
        ↓
16:9 Shot Master
        ↓
Reference Binding
  ├─ identity refs (same subject)
  ├─ guide frame (optional)
  ├─ motion ref (optional)
  └─ last frame (optional)
        ↓
MiniMax H3 @ native 24fps
        ↓
720p / 24fps / 5s default
480p / 24fps / 5s preview
        ↓
QA / Promote
        ↓
Chapter Edit / TTS / Subtitle / BGM
```

核心原则只有一句：

> **先把镜头画对，再让它动；H3 保持原生 24fps，参考素材各司其职，不让模型在视频阶段重新猜一次场景和人物关系。**
