# 本地 9B 模型分镜生成评审与设计

逐场处理适合作为分镜规划的执行边界，但固定每场两镜不能保证内容完整。推荐由程序负责预算、引用、顺序、配额和持久化，让本地模型在单场上下文中完成有限的事实选择与表达。视觉事实来源、中文契约、英文译文和采纳检查必须使用同一份数据契约。

评审日期为 2026 年 10 月 8 日，代码基线为 `dfc90d8`。本文是待实施设计；本轮只运行隔离诊断与模型测试，没有生成第二章候选或修改正式时间线。

## 本机模型实测

加载文件为 `Huihui-Qwen3.5-9B-abliterated.Q4_K_M.gguf`，API 别名为 `novastory-qwen3.5:9b`。服务报告上下文 16384 token、一个推理槽位。评估针对这个具体量化模型和当前配置，不外推为所有 Qwen 或 9B 模型的能力。

共执行 50 次真实本地模型请求，全部采用非露骨合成素材。主评估包含 24 次翻译、2 次分类、12 次审查、1 次整章规划及9 次逐场规划；另有2 次长段落事实摘录。翻译和分类使用种子41、97，温度对比0.85与0.1；未开启推理模式。

| 能力 | 实测结果 | 设计含义 |
| --- | --- | --- |
| 现有生图标签式翻译 | 无人庭院在两个种子、两种温度下均被添加人物 | 仅降低温度不能修复任务定义；翻译任务不应同时要求创作生图标签 |
| 编号短事实翻译 | 8份输出较好保留颜色、左右手、否定和递交关系；仍出现“扶住”被译为“支撑”的措辞偏差 | 适合小批量直译，不能宣布语义零错误；此组事实由评估者预先拆分 |
| 单句模态分类 | 8句，两个种子均8/8 | 可辅助标记视觉、声音、心理和比喻；简单分类成绩不代表长段落摘录能力 |
| 长段落可见事实摘录 | 三段、两个种子；预设关键线索均保留且摘录均为原文子串，但其中一段在两次输出中都混入钟声和寂静 | 模型不能独自决定何为“可见”；必须保留来源和不确定状态 |
| 原有证据式审查 | 6个对照案例中5个判定符合预期，漏过新增人物 | 单向“原文是否出现”不足以证明译文忠实 |
| 简短双向判定 | 同6个案例均符合预期 | 可作为辅助审查；样本很小，同一模型自审不是独立正确性证明 |
| 整章九场完整契约 | 34.779秒，9镜、27/27块引用，未出现无效或重复ID；同时出现自行增添环境和合并连续动作 | 不能断言9B绝对无法输出整章JSON；结构通过不等于视觉忠实 |
| 九场仅分配块引用 | 合计10.331秒，18组，27/27引用按序覆盖，9场均满足每场2组上限 | 缩小模型职责有收益。此结果不包含完整中文契约、翻译和审查，不能据此宣称完整生成快3倍 |

## 对逐场两镜方案的对抗式评审

| 严重性 | 反例或实现冲突 | 必须补充的设计 |
| --- | --- | --- |
| P1 | 每场2镜是由这章9场凑成18镜。四个不能同时发生的动作仍塞不进两个关键画面；单个动作块也可能包含多个状态变化 | 按必须呈现的视觉节拍计算最小预算，不能按场号或动作块数量硬编码 |
| P1 | 模型返回短 `primary_action` 后，`resolvePrimaryAction` 仍把已分配的全部action原文连接起来覆盖短句 | 调整事实来源和契约解析机制，生成、编辑、验证、采纳一起迁移 |
| P1 | 把一个大块ID挂到镜头上，再只保留其中一句，块覆盖率可以100%，其他可见动作却完全未上画面 | 增加事实级来源与覆盖，不把ID出现当成画面已覆盖 |
| P1 | 一块含多个独立动作，合理拆镜需要同块出现在多个镜头；现有重复检查对所有block_id一律拒绝 | 有声块保持唯一归属；视觉事实按fact_id覆盖，source_block_id允许有多个来源片段 |
| P1 | 生成侧改成摘录短句，采纳侧仍要求 `vis_` 块或visibleBeats的完整原文出现在primary_action，并重新调用同模型逐镜审核 | 定义版本化事实契约和审核记录，避免两个阶段使用不同覆盖定义 |
| P1 | 九场全部翻译后才做全局景别配额，最终失败仍浪费前面所有工作 | 先分配可行预算和景别，再生成；最后复核，修复只影响必要分场 |
| P1 | 只审核服装、姿态、接触、道具、地点，会漏掉人物身份、数量、谁对谁做了什么、颜色和否定 | 审核维度来自每个镜头的结构化事实；不同题材共用同一机制 |
| P2 | “上一场最后一句”可能是对白、音效或比喻，缺少持物状态、站位和服装连续性 | 传递有来源的简短状态摘要，未知字段保持未知 |
| P2 | 把对白“供旁白使用”会混淆对白、画外音与音效 | 沿用现有三个独立通道，程序逐字装配，保留说话人、归属和相对顺序 |
| P2 | “一场失败只重试这一场”没有说明进程中断、并发点击和修订变更后的恢复 | 持久化分场结果、唯一请求键和依赖版本；更细的译文失败只重试该镜 |
| P2 | 单场本身可能超长，逐场调用也会超出稳定工作范围 | 仅在单场超预算时，按完整叙事节拍分组；每组独立完整JSON，保留场内顺序与状态，不续写JSON |

相关代码：`storyboard_generation_service.ts` 的 `resolvePrimaryAction`、`compactStoryboardShots`、`validateStoryboardCoverage`、`validatePayload`、`applyStoryboardCandidate`，以及 `script.ts` 中候选20镜上限。当前正常路径通常一次生成全章规划；代码另有一次超限重写机会，机械合并通常让它失去触发条件。第一镜核对失败时，后面镜头尚未逐镜翻译；被浪费的是全章规划和已完成的前置工作。

## 针对特定文本的代码问题

`english_visual_prompt.ts` 存在固定人物、地点、道具名称词典，以及按具体原文短语放行的分支。项目资产的专名译法适合存为项目数据，通用语义检查不应依赖这些人物或作品。

对 `visibleFactPresent` 的确定性反例：令审核器明确返回missing，原文为“门扉半掩且门外有三只白猫”，英文只有 `A half-open door.`，当前函数仍接受。把原文换成同义的“木门半开且门外有三只白猫”，函数才拒绝。该测试使用模拟审核结果隔离规则本身，证明问题来自程序中的词句例外，而非这次模型采样。

这类例外应删除或改为事实级的通用检查；单个词命中不得豁免整条包含多个事实的句子。测试素材也应变换人物名、地点、物品、措辞和叙事顺序，防止以修复某章替代泛化能力。

## 通用处理流程

程序冻结剧本来源 → 按场建立事实来源 → 分配镜头与景别预算 → 按场规划 → 小批量直译 → 程序校验与局部语义审查 → 整章复核 → 保存候选 → 用户采纳。

这是固定步骤的工作流，不需要增加模型自主调度或多代理。把任务拆成明确步骤，并在步骤间进行程序检查，符合可测量的小任务工作流方法；本机只有一个模型槽位，因此推理串行执行。[工作流方法参考](https://www.anthropic.com/engineering/building-effective-agents)

### 事实与来源

保留原始剧本不变。每场建立轻量中间表示，至少包含：

| 数据 | 用途 | 责任边界 |
| --- | --- | --- |
| 来源片段 | block_id、原文引用、程序定位的起止位置 | 模型可建议原文摘录；程序验证必须是真实连续子串，重复匹配不能猜位置 |
| 视觉事实 | 必填fact_id与原文来源；按需要附加主体、对象、数量、颜色、左右和否定等约束 | 不要求9B一次抽出完整关系图。约束必须能回溯来源，无法可靠解析的部分保留原文并标记待核对 |
| 有声内容 | 原始对白、画外音、音效及顺序 | 程序直接复制，模型只参与与视觉节拍的对齐建议 |
| 状态摘要 | 地点、人物在场、服装状态、道具持有者、进出和未完成动作 | 优先使用剧本与资产中的显式数据；推断与事实分开 |
| 镜头规划 | 主动作事实、兼容的状态事实、声音归属、来源 | 模型在单场内选择，程序检查覆盖、顺序和预算 |

分类支持visual、audio、internal、figurative、mixed、uncertain。已标为sound或dialogue的原始块无需再让模型猜类型。action块内部混合内容不可整句丢弃，也不可整体当成图像事实。所有来源片段应有处理结果，避免抽取时悄悄遗漏；处理结果包括保留、明确排除以及需要核对。程序可以检查片段和引用完整性，但不能据此声称语义分类一定正确。

画面事实和连续动作分开。一个关键帧不能同时表达相互矛盾的前后状态；需要多个画面的关键动作进入不同镜头，连续动作的时间关系保留到运动描述。不得为了240字上限截断事实。

### 预算分配

当前候选格式继续以20镜为章级产品约束。这个约束与模型单次输出能力分开配置，不以“9B模型”为理由固定成每场两镜。

程序根据经确认的必要视觉节拍、场内状态切换和有声内容时长得到每场最小镜数，再在总预算内分配可选镜头。场景时长与预计语音时长参与可行性检查，镜头数量满足不意味着声音能塞进时长。

若最小镜数之和超过20，返回可解释的预算冲突：哪些事实需要独立镜头、最少需要多少镜、有哪些非关键内容可由用户选择简化。不得循环要求模型压缩，也不得通过静默并镜或丢引用满足数量。

先完成章级配额规划，再把本场可用的镜头类型传给模型。现有配额检查保留为最终复核；配额修复要同步调整构图等关联字段，不能只改标签。画面完全重复需要检查，但对话反打、重复建立镜头和有明确叙事用途的回访不应因为相似就无条件删除。

### 单场模型任务

每次提供当前场的内容、允许引用的ID、本场资产、可用镜头预算和已确认的连续性状态。优先使用ID和枚举选择，减少重复输出人物、地点和原文的机会。程序填写固定来源、顺序、声音原文以及能直接从资产库读取的字段。

模型优先输出本场各镜的fact_id组合与主动作选择，只有需要自然表达时再输出短中文句。完整必要事实保存在事实列表，primary_action用于概括一个主要可见动作，不再承担容纳全部原文的职责。Schema限定本场ID、允许的枚举和输出数量；随后仍由代码检查重复、漏项、跨场引用、顺序和可行性。语法约束不能代替语义与跨项检查。[llama.cpp结构约束说明](https://github.com/ggml-org/llama.cpp/blob/master/grammars/README.md#json-schemas--gbnf)

本场失败保留其他已通过结果。若失败只涉及某镜英文，则不重新规划本场。单场过大时，只能在明确的叙事节拍边界分批；每批是独立请求，带稳定ID和状态。禁止让模型接着补前一段JSON，禁止机械地把每个动作块变成一个请求。

### 英文生成与审核

翻译输入使用编号事实和项目词典，目标是短句直译。镜头类型、画风、构图、权重与技术标签由后续编译器拼装。最终编译结果仍要核对，防止标签或人物外观锁与当前事实冲突。英文生成按镜组织，可在同一请求翻译该镜的少量事实，不要求一个事实一次网络请求。

模型审查用较小任务判断遗漏、矛盾与新增，不要求同时生成长解释和严格逐字证据。返回有问题的fact_id与原因枚举；缺少证据或JSON格式错误属于审核格式错误，不等同于译文失真。人物身份、数量、动作施受关系、颜色、状态、左右、否定和地点都按来源事实核对。

程序硬检查ID、Schema、字符语言、事实和声音覆盖、版本、互斥的已结构化状态；同模型语义审查仅作补充。翻译失败把明确问题反馈给该镜，最多一次修复后再审。无法消除的不确定性展示为待核对，并保留已完成结果，不通过作品特定短语直接放行。

候选审核记录绑定事实内容、完整译文、模型、提示词和校验器版本的哈希。保存或采纳前若内容未变，可复用服务器生成的有效记录；人工编辑任何相关内容立即使记录失效。没有有效记录的旧候选需先审核。采纳事务仍重新检查来源修订、候选修订、正式时间线状态与替换保护，不信任客户端提交的“已通过”标记。

### 调度与恢复

分场规划和译文结果写入生成任务记录，正式时间线只在最后采纳事务中修改。复用现有任务基础设施，避免另起一套通用代理框架。

请求幂等键需要在生成前占位，而不是只在成功候选表里查找。相同键和输入返回同一任务；相同键不同输入返回冲突。任务记录包括剧本版本、资产版本、模型指纹、策略版本、本场输入哈希、前序状态哈希和阶段结果。前场重做改变连续性时，只使依赖该状态的下游结果失效。

界面展示具体场、镜、阶段及待核对事实。网络断开或重启后读取任务状态恢复；服务故障和语义不确定分别呈现。单场的确定性失败不必阻止无依赖分场继续处理，但依赖未知前态的分场不能假装连续性已成立。只有所有必需结果完成并通过整章复核，才形成可采纳候选。

长任务可返回202和任务地址，通过现有进度机制查询；失败或完成状态持久化。[异步请求与幂等参考](https://learn.microsoft.com/en-us/azure/architecture/patterns/asynchronous-request-reply)

以下是根据此次小样本拟定的初始配置，不是已测得的模型硬极限。复杂场次和不同题材需要后续校准。

## 迁移与验收

建议按一个纵向闭环实施：先增加事实来源契约和兼容读取，接通逐场规划及局部重试，再接通翻译和审核，最后同步候选编辑、采纳与任务恢复。新候选使用新版本契约，旧候选保留兼容验证路径；不能把旧候选自动标为通过。

| 验收案例 | 必须满足的结果 |
| --- | --- |
| 1场、9场、12场，动作密度不同 | 不依赖场号或固定每场2镜；每次模型规划只接收自己的场或节拍组 |
| 单块含多个动作、多个状态 | 可以拆分事实来源，完整覆盖，镜头不得包含互斥状态 |
| 声音、心理、比喻混入action | 可见事实保留；非视觉内容不进入英文画面门禁；歧义可见且可处理 |
| 多人、动物、无人、道具空镜 | 不新增主体；不漏数量、施受关系、颜色、左右与否定 |
| 修改人物名、地点、道具与同义词 | 相同语义得到一致门禁结果，不依赖示例作品词典 |
| 对白、画外音、音效 | 各自原文、说话人和顺序保持；有声内容不重复分配 |
| 单镜动作超长、最低预算大于20 | 返回局部或预算冲突；不截断，不静默并镜，不整章盲重试 |
| 第1场第1镜或最后1场失败 | 已通过结果可恢复，重试只触及失败项及其真实依赖 |
| 配额或去重冲突 | 在翻译前尽量发现；最终复核一致，局部修复不伪造覆盖 |
| 连续点击、断线、进程重启 | 幂等任务可恢复，不创建重复候选 |
| 编辑候选或生成中修改剧本 | 相关审核记录失效；版本冲突拒绝采纳 |
| 生成通过后采纳 | 不因再次随机自审出现无依据翻转；篡改后仍会被重新审核和拒绝 |
| 任一失败与部分结果 | 正式时间线不变，待核对内容不能被当成可采纳完成品 |

发布前应使用至少三个不同题材、多个固定种子建立真实模型回归集，分别统计完整率、错误新增率、审核误拒率、局部恢复成功率和耗时分布。当前50次能力探针为设计提供方向，不能代替这些端到端验收。

## 实施记录（2026-10-08）

上文保留评审时的原始结论。本节记录已实现的纵向闭环，以当前代码和测试结果为准。测试均使用合成素材和内存数据库，没有生成正式章节候选或改写正式时间线。

### 已落地的契约与执行边界

- 新候选使用 `schemaVersion: 2` 和 `storyboard-facts-2` 策略。事实保留场、块、原文、起止偏移、分类、节拍和有来源的状态；程序核对完整来源分区、重复片段定位与顺序。混合、不确定或单句包含连续动作的片段进入人工核对，不截断原文。
- 来源短片段由程序固定；模型分别执行模态分类、单画面可表达性、相邻片段时间关系和状态提取。状态提取按单条事实执行，主体优先受项目资产名称约束，状态值必须为该条原文的真实子串。此前多事实状态提取会串填衣着和持物，已保留失败记录并缩小任务。
- 预算按已确认节拍、预计场景时长与语音时长计算，章级上限仍为20镜。超过预算、单条语音超过15秒或无法保持声音顺序时明确拒绝。景别与特写可行性在翻译前检查；特写必须存在已声明且原文出现的道具。
- 程序固定完整节拍的事实组合和顺序，模型只从各镜允许ID中选择主事实。一个场可有1镜、4镜或更多镜；超长场按完整节拍分组。主动作是选中事实的原文，完整事实单独保存，不再拼接整块覆盖短句。保持镜使用独立的 `hold_fact_ids` 沿用本场前画面，不能借保持镜伪造首次覆盖。
- 逐镜按少量编号事实直译，镜头、权重和外观锁由编译器装配。人物及道具译名取自新增的项目资产 `english_name` 字段。移除了固定作品专名词典、门句与香气等短语豁免、自动补画面短语及审核失败后的放行路径。
- 对白、画外音和音效按原文装配，完整有声块连同说话人和语气字段写入镜头契约。action中明确分类为audio的片段有独立ID及唯一归属，并进入音效通道；心理、比喻和待核对片段保留在事实契约，不混进英文画面。
- 人物在场、服装、持物、位置及未完成动作使用带事实来源的状态。跨地点不继承旧地点的站位、在场与待完成动作；适用的衣着、持物状态参与下一场输入、英文直译和最终审核。未提取的字段保持未知。
- 生成、候选编辑和采纳共用v2来源、覆盖、预算、声音、状态、资产字段及负面提示词校验。双向语义审查采用小任务的 `faithful` 判定，含遗漏、矛盾、新增、身份、数量、施受关系、颜色、左右与否定；失败返回本镜事实ID，最多修复一次。多字段审核曾误报新增，失败样本保留，没有通过豁免消除失败。
- 审核记录只由服务器写入，绑定来源、事实、完整镜头内容、模型配置、资产内容和策略哈希；未变内容复用，编辑或资产译名变化后重新审核。事实分类契约另有服务器确认记录，客户端不能靠改分类或提交“已通过”绕过门禁。旧候选仍走兼容审核，但审核输入包含其引用的原始动作，不能只审短主动作。
- 复用 `generation_task` 持久化请求占位、分场事实、规划、已通过镜头、状态依赖和耗时。相同请求键合流，相同键不同输入拒绝；模型任务及候选重新审核串行执行。失败和重启保留进度，界面支持核对分类、拆分原文、修改节拍与源引状态，然后从通过结果继续。前场状态改变只使真正依赖该状态的下游失效。
- 长任务接口支持202，保留同步接口兼容。完成所有门禁才保存候选；采纳事务继续检查来源和候选修订、旧时间线、正在制作任务、已验收视频及替换场景清单，并保存被替换时间线快照。

主要入口为 `backend/src/services/storyboard_fact_workflow.ts`、`backend/src/services/ai/storyboard_generation_service.ts`、`backend/src/schemas/storyboard_facts.ts` 和 `components/Director/DirectorStoryboardCandidates.tsx`。数据库迁移022为人物和资产增加译名字段，旧数据默认空字符串。

### 明确保留的边界

程序能证明来源、分区、ID、引用、顺序、时长预算和已结构化状态一致，不能独立证明自然语言语义。分类、节拍与状态仍有模型辅助；同模型自审通过和上述小样本通过，不构成零错误或独立正确性证明。人工核对入口保留，无法消除的不确定性不形成完成候选。

语音时长目前按每秒4个非空白字符估算，单镜15秒为当前工作流约束，尚未接真实配音时长或运动生成。运行任务绑定的是模型名称与服务配置哈希，尚未计算GGUF文件内容摘要；用相同别名和配置替换权重后应使用新请求并重新生成审核记录。中断任务由用户在界面继续，当前不会在服务重启后自动恢复推理。事实输入超预算或连续状态过长会明确要求核对，不做静默截断。

## 本地改动评审修复（2026-10-09）

本轮处理评审提出的3个缺陷及1条资产建议，保留原有未提交改动。

- **恢复任务的确认时点**：失败、中断和取消任务用条件更新先持久化为 `queued`，清除旧错误并递增 `attempt`，再返回202。保留已通过的分场和镜头检查点；同轮请求合流，队列键包含轮次，避免接上上一轮尚未清理的失败承诺。接口返回轮次，轮询忽略旧轮次终态，但本轮快速失败仍立即显示。刷新恢复另外比较任务更新时间，避免旧失败结束新任务的监听。
- **道具特写的共同条件**：生成规划与最终校验共用 `visiblePropEvidence`，只对已声明、且视觉事实中有该名称原文证据的道具要求特写；仅有 `propIds` 不再制造不可满足的配额。特写镜自身也必须有可见道具来源。确有可见道具却缺少特写时，错误列出分场ID和道具名。当前名称匹配仍是来源逐字匹配，不推断同义名称对应同一资产。
- **按换行拆分事实**：拆为N段后，将同场后续节拍统一顺延N−1；其他场次不变。新段标记待核对并清除旧状态证据，防止拆分后沿用不再对应片段的状态。
- **只修改资产译名**：保留原图片、状态与任务编号；外观字段改变时仍清空生成结果。保留修订冲突及生成中禁止编辑保护，更新时直接保留数据库当前图片字段，避免覆盖并发完成的生成结果。资产修订仍递增，既有引用继续沿用原修订核对规则。
