## 修复前已复现的缺口

| 优先级 | 确定性反例或代码行为 | 实际影响 |
| --- | --- | --- |
| P1 | 事件“林岚把蓝伞递给陈月”，用“陈月把蓝伞递给林岚”检查，`verifyEventContentCoverage` 返回 true | 名字和物品都在，动作方向仍可颠倒；事件覆盖率不能代表改编忠实 |

| P1 | 同样的后句，`subjectEvidence` 仍接受已离开的林岚，因为姓名在同场此前出现过 | 历史提及被当成当前人物证据；没有依据进出场排除候选 |
| P1 | 当前句“陈月穿蓝色外套”，前文提过林岚；将“蓝色外套”挂给林岚，状态证据函数仍接受 | 原文子串检查证明词语存在，却没有证明谁穿这件衣服 |
| P1 | 林岚先穿蓝色外套，再戴红色围巾，两个状态都用 `wardrobe`；后者覆盖前者 | 一个人只能保留一项服装值，衣着层次及多个持物也有类似表示问题 |
| P1 | 下一场动作只有“她举起蓝伞”，虽有角色 ID，前场衣着仍因本场未出现姓名原文而不继承 | 跨场代词可能丢失既有外观与持物状态 |

以上 6 组反例是修复前基线；完整工作流的输入对照使用模拟模型，证明当时模型选错且自审通过时程序不能兜底，不是实际模型错误率。[复现入口](../../local/verification/pronoun-fact-audit-20261009.ts)和[结果](../../local/verification/pronoun-fact-audit-20261009.json)保留原始记录，不用新实现的结果覆盖它们。

复核还确认了以下边界，已据此调整实施：

- `stripUngroundedMalePronouns` 在当前事实没有汉字“他”时删除英文 `he/him/his`。中文可省略主语，也可直接写男性姓名；这条规则既没有解析身份，也可能删除正确的所有格或动作对象。应通过绑定修复整句，不能靠删除词语建立正确性。
- `literalNames` 将当前事实中出现的姓名直接加入可见人物。例如“桌上放着陈月的照片”不等于陈月本人入镜；所有者、被提及者、画像和画外说话人需要区别。
- `extractVisibleBeats` 依赖服装、姿态和接触关键词，默认最多 16 项，不是通用视觉事实提取器。普通物件、数量、颜色、背景等没有同等保留保障。
- 来源回填不仅有按序号兜底，还有双向子串包含：错误事件也可能得到真实段落 ID。现在无可核对来源就拒绝；有合法 ID 也要核对原文绑定和改编关系。
- 分镜翻译的地点输入主要为地点名称；结构化 `timeOfDay`、内外景和地点描述没有在该输入中系统装配。仅存在于这些字段中的“夜间、室外、白墙”等信息可能没有进入画面事实。

镜头规划原本看得到前面的节拍事实，但只能输出事实 ID，不能保存“她是谁”；负责选择人物的调用却没有前文。同块前文原本就进入状态抽取，因此不能修成“姓名和衣物必须同句”。原通过用例还要求衣着覆盖和删除 `him`，本轮已改为保留逐件衣物及拒绝整句错误译文。

此外，原 `actionOverridesWardrobe` 会因一人解衣改掉同镜全部人物服装；直接生成时间线的 HTTP 和 Agent 路径绕过事实工作流。本轮改为按穿戴者和衣物调整资产锁，并明确停用两条直写旁路。

事件覆盖原二字片段阈值不能解决施受交换：8 片段重合 6 个的比例为 0.75，阈值提到 0.7 仍放行。本轮移除词面相似兜底；明确递交关系按施事、物件、受事比较，同关系的“被”字句允许通过。其他未识别改写保守待核对，不能把模型自审当作独立证明。

## 分镜事实必须覆盖的内容

按“会改变画面或叙事理解的事实”提取，并允许未说明。不要要求模型为每个字段编一个值。

| 类别 | 必须关注 | 常见错误与处理要求 |
| --- | --- | --- |
| 人物身份 | 稳定人物 ID、姓名、已确认别名、称谓、代词、省略主语、群体与数量 | 同名、昵称和职位不可随意合并；不能从姓名猜性别，也不能仅靠性别决定指代 |
| 人物是否可见 | 入场、离场、遮挡、画外、被提及、画像、倒影、梦境中的人物 | “被说到”不等于“在现场”，“在现场”也不等于“被当前构图拍到” |
| 动作角色 | 谁执行、作用于谁、交给谁、使用什么；身体部位属于谁 | “甲扶乙的左臂”必须锁定甲为施事、乙为身体部位所有者；接收者不能被换成递交者 |
| 外貌与身份连续性 | 年龄阶段、发型、肤色、体型、标记、伤势、变装 | 稳定角色外观与本场变化分开；回忆中的年轻角色不能直接用当前年龄 |
| 衣着 | 穿戴者、具体衣物、层次、颜色、材质及穿上、脱下、敞开、湿透等状态 | 脱外套不等于脱全部衣服；新增围巾不能覆盖外套；两个人的衣着不能混用 |
| 道具 | 实物 ID、名称与别名、数量、外观、位置、持有者、使用者、完好状态 | 所有者不等于持有者；递交前后要解除旧持有关系；多个物件分别记录 |
| 空间与接触 | 相对位置、朝向、视线、距离、支撑与接触点、左右归属 | 角色左手与画面左侧不同；“在门左侧”必须指明参照物；接近不等于接触 |
| 背景与场所 | 地点 ID、内外景、固定布局、门窗状态、布景物、群众、动物、标识 | 无人画面不能补路人；空镜中存在动物不等于“没有任何主体” |
| 时间与环境 | 日夜、天气、季节、照明来源、同一时刻或先后、跳时与回忆 | 夜间不能只留在剧本元数据；跨时间段不得无条件继承衣着、伤势、道具 |
| 否定与不确定 | 未发生、没有接触、尚未完成、想要、可能、条件句、传闻 | “想推门”不等于门已打开；“没拿杯子”不等于手持空杯；未知不等于没有 |
| 声音与叙事层 | 对白、说话人、受话人、画外音、音效、心理和比喻 | “她说‘他回来了’”不能自动生出他入镜；内心和比喻不能被直接画成现实物体 |
| 动作阶段 | 动作前、进行中、动作后，是否能共处一个关键帧 | 坐下后站起不能塞入同一静帧；关键帧与后续视频动作分别表示 |

事实完整不要求每镜都露出所有细节。关键身份、动作关系与剧情物件属于硬约束；次要材质和装饰可沿用已确认资产。近景裁掉鞋子是构图选择，不能因此把鞋子从人物持续状态中删除。需要呈现的重要细节另分配镜头。

## 共用人物绑定和事实来源

推荐流程：小说原文定位 → 人物提及与指代绑定 → 必保事件 → 分场改编 → 分场事实核对 → 镜头规划 → 英文表达 → 编译后核对。

同一版文本的已确认绑定随版本传递。提纲、剧本和分镜使用同一实体 ID；小说和改编动作分别保存偏移，改写后重新生成绑定，不能共享旧偏移。固定步骤加程序检查适合当前流程，[工作流参考](https://www.anthropic.com/engineering/building-effective-agents)。

### 保留原文并单独保存解释

事实原文、段落或块 ID、起止偏移保持不变。另保存“这个代词对应谁”的解释，不能为了写成姓名而替换原文后还沿用旧偏移。偏移统一使用项目字符串索引的口径，避免 Unicode 字符计数方式混用。

最小新增结构包括：

- **实体**：`entity_id`、类型、规范姓名、已确认别名。无姓名但确实存在的人物可用场内临时 ID，不强制凭空创建角色档案。
- **提及与绑定**：当前词句范围、候选 ID、选定 ID 或 `null`、前文证据、`resolved/ambiguous/unknown`、确认来源及 `visible/mentioned/uncertain`。当前实现用单实体绑定；群体多实体是后续扩展，不把候选数组当可见实体数组。
- **关系事实**：来源事实 ID，以及必要的 `actor/target/recipient/instrument/body_part_owner`。仅在相关事实中填写，不要求小模型一次生成完整关系图。
- **状态变化**：实体 ID、具体衣物或道具 ID、属性、状态值、变更动作、有效时间段、来源事实 ID。
- **事实依据**：原文明确、根据上下文消解、从前态继承、已采纳改编、新增设计、未知。来源类别与解析是否确定分开存。

模型可以建议关系，程序验证 ID、偏移、来源和互斥条件。当前模型建议即使 `resolved` 也为 `confirmed:false`；无歧义的同动作块单人继承可以自动确认。人工核对必须同时看原文与改编句。“引用正确原文”和“可见姓名来自同一次模型选择”都不构成独立语义证明。

### 指代消解的具体规则

先精确匹配规范姓名与已确认别名。对于“她、自己、对方、前者、两人、她的”和省略主语，提供当前完整语句、必要的前文，以及当前仍适用的人物和状态。候选不足时补取有来源的上下文；不能只从截断后的候选中强选一个。

消解要同时区分施事、受事、所有者与受话人。引号中的“我、你”使用该段的说话人和受话人；“自己的”依赖当前句的语法关系，不能统一替换为最近的人名。对白可提供身份线索，但只有明确可见的部分才转成画面事实。

明确离场可排除当前现场角色；回忆、转场、说话人切换和人物重入场必须重新判断作用范围。距离最近、性别匹配、出场次数最多都只能提供线索，不能单独决定绑定。

“林岚看着陈月，她笑了”若没有其他依据，保留两个候选、选定实体为 null，等待核对；不让两人因此都入镜。明确写了离场和留下时，把相应完整前文交给短任务；当前短任务仍只给建议。单人同块“青禾解开外衣。她把里衣褪到腰间。”必须继续自动通过。不要让所有代词都阻塞整章，也不能为了通过率强行消歧。关键关系未确定的镜头不能采纳，已完成的无依赖工作保留。

### 三个入口分别负责什么

| 入口 | 应使用的输入 | 必须保存的结果与检查 |
| --- | --- | --- |
| 提纲 | 带来源的人物绑定、关键关系事实、原文段落 | 事件关联事实 ID；概括可精简，但不可交换人物角色；无来源不能按序号伪造；低层视觉事实留在共用事实层，无需全部挤进梗概 |
| 剧本 | 提纲事实、涉及角色、原文证据、上一场有效状态 | 动作中优先使用明确姓名；对白保留自然代词，并另存说话人和受话人；新增可表演动作标记为改编，不冒充原文；生成后比对关键角色关系 |
| 分镜 | 已确认剧本事实、有效绑定、入镜条件、资产与连续状态 | 不重复猜原文代词；依据关系决定可见人物；每镜动作关系、服装归属、道具状态、地点与日夜都能回溯；人工修改也经过同一校验 |

人物姓名显式化仅用于机器消费的事实表达和动作描述。不要全局替换小说或对白中的自然代词；也不要用人物 ID 校验替代关系审核。两个人都合法，依然可能被写反。

## 衣着和道具采用逐项状态

状态键应包含实体、物件和属性，而不是只有 `entity:wardrobe` 或 `entity:holding`。例如蓝色外套的穿戴状态、红色围巾的穿戴状态分别保存；递交伞记录为持有关系变化，不是再往接收者名下追加一句文本。

更新至少区分 `set/add/remove/clear/unknown`。明确“不再拿伞”可以清除持有关系；“没有提到伞”不能自动清除。原文只说递出、尚未接过时，不应提前判定转移完成。状态值允许保留原句，但需要结构化动作和物件来确定如何更新。

继承必须有范围：同一时段内稳定衣着可继承；位置跟随地点变化失效；换装、放下、离场、跳时、梦境和回忆分别处理。多个叙事时间层使用不同状态，不让回忆污染现实。状态未提取成功时保留待核对，不能悄悄丢掉后宣称该事实完整。

当前已确认场内事实优先于资产默认外观。资产提供稳定身份和获准的默认设计，不得覆盖明确的脱衣、湿衣或持物变化。只调整发生变化的那个人、那件衣物；不能因为某人改变衣着而删除同镜其他人的全部服装约束。

## 适配本地文本模型

以下区分实际采用参数与后续建议；它们不是能力上限。

| 项目 | 建议起点 | 原因 |
| --- | --- | --- |
| 推理并发 | 1 | 与已有单槽配置一致，避免抢占造成延迟失控 |
| 指代任务 | 当前事实中的待核对提及；一次短任务 | 不把整章改编、人物消解、镜头设计和翻译压进一次输出 |
| 上下文 | 提纲原段前 2 段；分镜同块前文、之前动作块及适用的同地点前场末尾；当前场所元数据 | 保留区分角色的证据；未来按证据补取更远上下文，不能硬截断后强选 |
| 输入规模 | 绑定任务当前事实加前文最多 2200 字符，超出转核对；完整系统词和输出另计 | 这是字符预算，不是 token 数。16384 也不等于稳定处理 16384 token 的语义能力 |
| 人物候选 | 按现场和话题筛选，常见 2 至 6 个；过多时扩大或拆分核对 | 不任意截掉真实候选，不要求选择不存在的选项 |
| 输出 | 绑定 maxTokens 256；翻译按小批事实、maxTokens 512 | 绑定只输出 ID 和状态；翻译绑定元数据只来自当前批次，禁止作为额外事实翻译 |
| 采样与修复 | 事实任务温度 0.1 起步；最多一次定向修复；服务重试单独计算 | 低温减少波动，不能弥补上下文缺失或歧义 |
| 歧义结果 | `null` 和待核对是合法输出 | 不用只能二选一的 Schema 强迫猜测，不把 `uncertain` 强制降成确定分类 |

结构化输出优先采用简单对象、ID 枚举和小数组；提示词也明确描述字段。llama.cpp 的 JSON Schema 用于约束输出，通常不会把 Schema 本身注入提示词，且仅支持部分特性；跨项唯一性和业务规则仍须程序检查。[llama.cpp 官方说明](https://github.com/ggml-org/llama.cpp/blob/master/grammars/README.md#json-schemas--gbnf)

事实契约保留原文及绑定；翻译使用姓名化事实和当前批次对应关系，不重复灌入整组未选原句。译文要求完整姓名及明确身体所有者；全项目词典只用于稳定译名，不能用它重新猜“她”。需要稳定实物、别名和更完整角色关系时再扩展结构，不能一次让 9B 生成庞大关系图。

每镜审核使用原文、绑定依据、关系、当前状态和译文；最后还要核对编译后组合，防止单句正确、合并后出现多人属性串位或资产外观冲突。同模型自审只提供辅助证据；已存在真正歧义、关键关系冲突或缺少来源时，不能用再次自审投票代替核对。

保留当前分阶段缓存和局部恢复。缓存依赖应包含原文版本、绑定、状态、资产、提示词、策略和模型配置；当前已把绑定加入来源哈希，复杂跨场依赖仍需进一步细化。记录实际权重版本，不能只依赖可复用的模型别名。

## 实施顺序

| 阶段 | 具体工作 | 完成条件 |
| --- | --- | --- |
| P0 确定性门禁与版本绑定 | 共用绑定、源文与改编分别定位、哈希失效、单人同块继承、多人物建议待核对、递交反转拒绝和被动同关系通过；同步落地逐件衣着、提及分离、完整场景输入和直写停用 | 代码门禁及小样本真实离场验收已通过；模型未被授权自动确认。完整本地流程尚有 2 个明确身体所有者译文待核对，不标为全部能力完成 |
| P1 完整关系和状态范围 | 稳定衣物/实物 ID、已确认别名、同类多件、持有与使用分离、通用动作角色/身体归属；入出场、天气、背景和时间层 | 增加人工标注集验证忠实改写及误拦截；一个人变化只改本人对应物件；跨时空不误继承 |
| P2 能力校准和恢复体验 | 持续真实 9B 回归、原句与人物选择并列、依赖失效和耗时统计；减少明确案例的人工负担 | 不靠更宽阈值、删词或模型自审降低错误率；测量后再决定哪些确定任务可自动接受 |

当前已同步修改共用绑定 schema、提纲与剧本生成、确认、导入复制、分镜契约、镜头契约、核对界面、采纳检查与缓存来源。界面可分别核对原文段落、改编事件、动作块或分镜事实的人物和可见性；明确改编释义可由用户核对后确认，不能被自动当作原文确定事实。

这是事实语义契约变化，应使用新的契约或策略版本。已有候选保留读取能力；缺少新绑定证据的候选不能自动获得新版本通过标记。原文、已采纳改编与用户明确更改的优先关系应可见，不静默用原文覆盖用户改编。

## 验收矩阵

| 案例 | 期望结果 |
| --- | --- |
| 同一后句，互换前文离场者与留下者 | 真实 9B 两种子 4/4 建议不同且正确；上下文哈希不同；建议全部待核对 |
| 单人同块“青禾解开外衣。她把里衣褪到腰间。” | 自动继承继续通过；外衣和里衣分别保存；不是姓名衣物必须同句 |
| 两名同性人物，“她”缺乏唯一依据 | 待核对，返回候选；不靠名字、性别或距离强选 |
| 跨动作块、省略主语、跨段或跨场指代 | 仍能引用适用前文；来源不够时提示缺少上下文 |
| 我、你、自己、对方、前者、两人、她的左手 | 说话人、受话人、群体成员和身体部位所有者分别正确 |
| 交换明确递交双方；同关系被动句 | 三阶段拒绝反转，被动句正例通过；通用扶持和追逐关系属于 P1，不冒充已验收 |
| 原文 ID 合法，改编把林轩举伞改成苏沐雪举伞 | 原文与改编各自保存绑定；改编姓名不能自动确认，也不能直接生成完整剧本 |
| 外套加围巾、脱外套、两人不同服装 | 保留层次、只更新对应衣物和穿戴者；未知不等于裸露 |
| 递伞、接伞、放下；同时拿两物；道具改称 | 分清进行中和完成；持有关系正确；经确认的别名沿用同一实物 ID |
| 照片、画外说话、被提及、离场和重入场 | 不把名字出现当成人物可见；人数和表现形式正确 |
| 无人背景、动物数量、门窗开闭、日夜和内外景 | 不增人、不漏关键背景；结构字段进入画面表达 |
| 角色左手、门左侧、画面左侧 | 各自保留参照对象；构图调整不能交换身体左右 |
| 未接触、想推门、听说返回、比喻及梦境 | 不把未发生或非现实内容当当前现实事实 |
| 连续时段、换地点、跳时、回忆和返回现实 | 状态按范围继承；不让旧站位或回忆衣着污染当前镜头 |
| 长章、超预算、失败恢复、人工改绑定 | 不截断关键来源；只重做失败项和真实依赖；正式时间线保持版本保护 |
| 旧候选、篡改人物绑定或场景字段；时间线直写 | 旧版必须重新生成；哈希/确认/采纳校验阻止变更绕过；HTTP 410、Agent 停用且原时间线不变 |

矩阵中除明确标注为当前实测/定向测试的项目外，完整群体、时间层、物件别名等仍是后续验收目标。建立人工标注的小型集，每类至少 3 个改名或改序变体，配合至少 2 个固定种子，再逐步扩大。这是建议，不代表足够估算罕见错误率。

验收同时记录：已自动接受绑定中的错误率、歧义被错误强解率、明确事实的完成率、角色关系反转、衣着串人、无依据新增、误拦截、请求次数以及 P50/P95 延迟。明确案例被全拦截也不算成功；正确性与自动完成率一起报告。固定验收集中的关键人物和关系错误应为零，但不能据此宣称所有文本零错误。
